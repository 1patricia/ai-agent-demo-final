
# AI工具使用说明
本项目开发过程中使用AI作为辅助工具，用于减少重复工作、快速产出初稿。所有AI生成内容均经过人工审核、修改与验证，核心逻辑、业务规则最终由本人确认，不存在直接不经校验上线AI原始输出的情况。

## 1. AI工具使用范围及对应工作模块
项目全流程使用大模型辅助完成以下工作：
1. Prompt方案设计：梳理Agent执行规则、编写系统提示词初稿
2. 代码辅助：生成基础代码、调试报错、编写脚本、完成多后端适配改造
3. 文档撰写：项目说明、注释、文档初稿整理
4. 测试相关：批量生成初始测试用例、梳理异常场景，人工扩充偏见、越权、提示注入、隐私窃取等安全类边界用例，完成去重分类全覆盖
5. 绘图：生成Mermaid流程图、实体关系图初稿
6. 多后端适配改造：完成本地Ollama、DeepSeek云端API双调用层封装，实现一键切换算力来源

## 2. 人工校验覆盖范围
所有AI产出内容落地前均进行人工核查，重点校验内容包括：
1. 业务规则：AI给出的判定标准、评分逻辑逐一核对，不符合需求的地方手动调整；
2. 代码逻辑：检查边界条件、异常处理、潜在缺陷，重构不完善代码；
3. 评测用例：剔除重复场景，补充边界、恶意输入等遗漏场景，修正错误预期结果；
4. JSON输出结构：规范输出格式，修复语法错误，统一数据结构约束；同时通过统一`MAX_TOKENS`约束输出长度，避免输出截断造成不完整JSON；
5. 架构图表：修正实体关系、排版问题，保证图表和实际业务模型一致。

## 3. AI生成内容典型问题、发现方式与修正措施
开发期间多次发现AI输出存在逻辑漏洞，主要问题整理如下：
1. **方案偏向全自动判定，缺少人工复核机制**
发现方式：梳理业务评审规则时识别隐患
问题描述：AI最初提出直接依靠模型输出生成最终评级，完全取消人工干预。
修正：新增`human_decision_required`标识，重要判定结果强制支持人工复核，模型输出仅作为参考依据。

2. **安全设计存在疏漏，未考虑提示词注入风险**
发现方式：人工构造异常测试用例时发现漏洞
问题描述：初始方案没有区分系统指令和用户输入，存在被恶意篡改执行逻辑的风险。
修正：增加输入清洗逻辑，隔离用户输入与系统Prompt，加固指令边界。

3. **信息判定逻辑混淆主观描述与客观证据**
发现方式：运行测试样例、核对评测结果时发现偏差
问题描述：AI容易把模型自身主观表述当成有效判定依据，而非依托客观材料进行评估。
修正：在提示词中明确数据源区分规则，增加校验逻辑，过滤无效主观说辞。

4. **生成JSON经常出现格式不规范、截断问题**
发现方式：程序解析文件报错、格式校验失败
问题描述：输出存在顶层多个独立对象、多余逗号、内容截断等非法格式。
修正：统一规定标准JSON结构，增加后置处理逻辑，规范输出格式；统一`MAX_TOKENS`参数限制输出token上限，规避截断。

5. **初始测试用例质量参差不齐**
发现方式：人工梳理测试集时发现
问题描述：大量场景重复，缺少高危异常场景覆盖。
修正：人工去重优化，主动补充空输入、超长文本、恶意注入等边界用例，完整覆盖正反证据、面试官冲突、偏见越权、隐私窃取、提示注入多类场景。

6. **云端模型额外输出多余分析文本，破坏JSON结构**
发现方式：切换DeepSeek云端API批量测试时批量解析报错
问题描述：本地Ollama量化模型更容易遵守纯JSON输出约束；DeepSeek V4会自动追加总结、自评文字，包裹有效JSON，导致程序无法正常提取结果。
修正：增加正则全局匹配截取最外层`{}`，过滤前后无关文本；同时强化系统提示词强制仅输出JSON，从源头减少冗余文字。

## 4. 使用原则
AI仅作为效率工具，用来完成初稿编写、重复性工作。
业务决策、安全设计、核心逻辑校验必须由人工完成。针对AI容易产生幻觉、逻辑疏漏的特点，建立固定复核清单，所有交付成果最终由本人负责。
针对本地笔记本算力不足问题，设计本地离线、云端在线双推理模式，日常演示优先使用云端API规避硬件瓶颈。
