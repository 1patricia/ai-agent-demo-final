

# 项目交付文档
## 一、本地完整环境部署、启动、验证步骤
1. 安装Ollama客户端
   前往 Ollama 官网下载安装包并完成安装，确保终端可以识别ollama指令
2. 拉取本地大模型
   ollama pull qwen:7b
3. 创建Python独立虚拟环境
   python -m venv venv
4. 安装项目依赖包
   pip install -r requirements.txt
   pip install ollama pydantic logging
5. 执行单条候选人测试用例
   python tests/single_test.py
6. 批量自动执行全部测试用例（完整测试集 21 条，覆盖正反证据、冲突面试官、证据不足、偏见越权、提示注入、隐私请求 6 大类边界场景）
   python tests/batch_eval.py
7. 查看评测输出
   运行结果统一输出至路径：`evaluation/results.json`



## 二、云端 DeepSeek API 无本地 GPU 运行方案
无需本地高性能显卡，依托第三方大模型 API 完成推理，上层脚本无需修改，一键切换模式。

### 1. 补充完整依赖安装
pip install openai python-dotenv ollama pydantic logging


### 2. 配置环境变量
在项目根目录创建 `.env` 文件，填入密钥与模型参数：
# 切换推理后端：ollama / deepseek
LLM_MODE=deepseek
# DeepSeek云端接口配置
DEEPSEEK_API_KEY=sk-你的密钥
DEEPSEEK_MODEL=你的模型
DEEPSEEK_BASE_URL=你的API地址


### 3. 运行命令与本地模式完全一致
```bash
# 单条测试
python tests/single_test.py
# 批量评测
python tests/batch_eval.py
```

### 4. 模式切换说明
通过环境变量 `LLM_MODE` 实现双后端无缝切换，业务调用层统一封装；本地`num_predict`与云端`max_tokens`共用`MAX_TOKENS`参数，保证本地、云端两套评测条件完全对齐。

## 三、材料定义区分
### 模拟材料事实（确定信息）
仓库内所有测试候选人文本、面试官记录，属于模拟招聘素材，仅用于技术验证；不包含任何真实求职者隐私信息。

### 个人业务假设（样板前置前提，记录于诊断文档）
- 岗位评估可以拆分为多条独立岗位成功标准（S1~S5）
- AI 仅负责客观证据抽取，不产出录用 / 淘汰最终决策
- 证据分为正向支持证据、反向冲突证据、无信息三种情况

### 待业务验证项（上线前必须由业务招聘团队确认）
- 岗位成功标准颗粒度划分方式是否适配企业现有招聘流程
- 证据可信度分级规则、风险标签定义是否匹配 HR 业务习惯
- 自动生成面试提问的使用尺度

全部边界说明同步记录于 `01-diagnosis.md`，作为业务基线。

## 四、业务侧 Agent Driver 日常配置与长期维护清单
业务运营人员可持续维护 5 类核心配置文件，持续优化 Agent 效果：
1. **岗位标准库**：各岗位成功标准结构化 JSON 文件（S1-SN 定义）
2. **风险拦截正则库**：敏感属性识别规则（年龄、性别、婚育信息匹配拦截）
3. **面试题库模板**：不同证据缺口对应的标准化追问模板
4. **测试用例库**：`test_cases.json`，包含基础业务案例、证据缺失、面试官观点冲突、招聘偏见、越权指令、中英文提示词注入、隐私窃取等安全攻防测试用例
5. **历史参考案例库**：过往人工复核后的标准证据抽取结果，用于后续 FewShot 优化

## 五、标准化流程：业务人员自查 AI 错误、反馈、迭代规则流程
1. 业务人员打开`results.json`核对 AI 输出证据，重点校验：证据溯源错误、证据遗漏、错误推断
2. 发现 AI 错误后，在测试用例库内标记异常 case，填写错误类型（格式错误 / 证据错配 / 幻觉新增信息）
3. 将错误用例纳入下一轮批量测试集
4. 根据错误类型迭代优化：调整 Prompt、扩充 FewShot 样例、更新风险拦截正则
5. 完成优化后重新执行`batch_eval.py`复测，验证缺陷是否修复

## 六、增量迭代优先级规划（假设额外拥有 1 天开发时间）
### 最高优先级：优化输入输出结构防护与异常兜底逻辑
理由：
1. 招聘场景输入文本长短不一、格式杂乱，LLM 极易出现 JSON 格式崩坏、输出幻觉；强化熔断、异常兜底可以避免无结构脏数据流入业务人员工作台。
2. 当前样板最大不稳定风险就是模型输出不可控，结构防护可以先保障系统可用性；精度优化属于次级迭代目标。
3. 云端模型易附带额外自评文字，增加正则 JSON 截取兜底逻辑，持续完善兼容处理。

次级优先级：扩充 FewShot 标准样例，提升证据匹配准确度；
延后优先级：丰富面试问题生成逻辑、细化可信度分级策略。

## 七、重要风险声明
本仓库代码为技术验证样板，存在多重硬性限制，无法直接线上落地真实招聘：
1. **隐私风险**：缺少企业数据脱敏、本地数据访问权限管控机制，未设计求职者信息安全管控；调用第三方云端 API 会将候选人文本传出本地，真实线上需增加本地文本脱敏预处理，规避外部接口数据泄露风险。
2. **评测样本不足**：测试素材量级有限，无法覆盖全部岗位、各类候选人文本场景，泛化能力未验证；
3. **缺少合规审批**：未完成人力资源算法公平性审核，无法规避招聘偏见隐患；
4. **无绩效回流闭环**：不存在「AI 评估结果→最终招聘人岗匹配效果」的数据回流链路，无法持续量化优化 AI 准确度；
5. **人机流程不完善**：缺少完整操作日志、人工复核留痕功能，不满足企业招聘审计要求。
