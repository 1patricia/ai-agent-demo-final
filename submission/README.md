# 项目交付文档
## 一、本地完整环境部署、启动、验证步骤
1. 安装Ollama客户端
   前往 Ollama 官网下载安装包并完成安装，确保终端可以识别ollama指令
2. 拉取本地大模型
   ollama pull qwen:7b
3. 创建Python独立虚拟环境
4. 安装项目依赖包
   pip install ollama pydantic logging
5. 执行单条候选人测试用例
   python tests/single_test.py
6. 批量自动执行全部测试用例（预设≥15条测试集）
   python tests/batch_eval.py
7. 查看评测输出
   运行结果统一输出至路径：`evaluation/results.json`

## 二、材料定义区分
1. **模拟材料事实（确定信息）**
    仓库内所有测试候选人文本、面试官记录，属于模拟招聘素材，仅用于技术验证；不包含任何真实求职者隐私信息。
2. **个人业务假设（样板前置前提，记录于诊断文档）**
    - 岗位评估可以拆分为多条独立岗位成功标准（S1~S5）
    - AI仅负责客观证据抽取，不产出录用/淘汰最终决策
    - 证据分为正向支持证据、反向冲突证据、无信息三种情况
3. **待业务验证项（上线前必须由业务招聘团队确认）**
    - 岗位成功标准颗粒度划分方式是否适配企业现有招聘流程
    - 证据可信度分级规则、风险标签定义是否匹配HR业务习惯
    - 自动生成面试提问的使用尺度

> 全部边界说明同步记录于 `01-diagnosis.md`，作为业务基线。

## 三、业务侧 Agent Driver 日常配置与长期维护清单
业务运营人员可持续维护5类核心配置文件，持续优化Agent效果：
1. 岗位标准库：各岗位成功标准结构化JSON文件（S1-SN定义）
2. 风险拦截正则库：敏感属性识别规则（年龄、性别、婚育信息匹配拦截）
3. 面试题库模板：不同证据缺口对应的标准化追问模板
4. 测试用例库：正向案例、证据缺失案例、冲突案例、LLM异常兜底案例（test_cases.json）
5. 历史参考案例库：过往人工复核后的标准证据抽取结果，用于后续FewShot优化

## 四、标准化流程：业务人员自查AI错误、反馈、迭代规则流程
1. 业务人员打开`results.json`核对AI输出证据，重点校验：证据溯源错误、证据遗漏、错误推断
2. 发现AI错误后，在测试用例库内标记异常case，填写错误类型（格式错误/证据错配/幻觉新增信息）
3. 将错误用例纳入下一轮批量测试集
4. 根据错误类型迭代优化：调整Prompt、扩充FewShot样例、更新风险拦截正则
5. 完成优化后重新执行`batch_eval.py`复测，验证缺陷是否修复

## 五、增量迭代优先级规划（假设额外拥有1天开发时间）
最高优先级：**优化输入输出结构防护与异常兜底逻辑**
理由：
1. 招聘场景输入文本长短不一、格式杂乱，LLM极易出现JSON格式崩坏、输出幻觉；强化熔断、异常兜底可以避免无结构脏数据流入业务人员工作台。
2. 当前样板最大不稳定风险就是模型输出不可控，结构防护可以先保障系统可用性；精度优化属于次级迭代目标。
次级优先级：扩充FewShot标准样例，提升证据匹配准确度；
延后优先级：丰富面试问题生成逻辑、细化可信度分级策略。

## 六、重要风险声明
本仓库代码为技术验证样板，存在多重硬性限制，无法直接线上落地真实招聘：
1. **隐私风险**：缺少企业数据脱敏、本地数据访问权限管控机制，未设计求职者信息安全管控；
2. **评测样本不足**：测试素材量级有限，无法覆盖全部岗位、各类候选人文本场景，泛化能力未验证；
3. **缺少合规审批**：未完成人力资源算法公平性审核，无法规避招聘偏见隐患；
4. **无绩效回流闭环**：不存在「AI评估结果→最终招聘人岗匹配效果」的数据回流链路，无法持续量化优化AI准确度；
5. **人机流程不完善**：缺少完整操作日志、人工复核留痕功能，不满足企业招聘审计要求。
